# PyVRP Web — 操作手冊

## 快速開始

### 1. 啟動伺服器

在專案根目錄執行：

```bash
uv run --python 3.11 python run_server.py
```

伺服器啟動後，開啟瀏覽器前往：

```
http://127.0.0.1:8000
```

## 操作流程

### 方法一：使用範例資料（推薦初次使用）

1. 點擊 Header 的「**載入範例 ▾**」按鈕
2. 從下拉選單選擇：
   - **7-11 台北市日班配送 (16 家門市)** — DC 09:30 出發，各店補貨窗口 10:00–13:00
   - **7-11 台北市大夜班配送 (16 家門市)** — 深夜補貨情境
3. 資料自動填入左側表單，地圖自動顯示所有位置
4. 點擊左側底部的「**開始計算**」按鈕
5. 等待求解完成（通常 5–15 秒），地圖自動繪製路線，右側顯示詳細資訊

---

### 方法二：手動輸入自訂資料

#### 步驟 1：填寫倉庫資訊

在「**倉庫**」卡片中填寫：

| 欄位 | 說明 | 範例 |
|---|---|---|
| 倉庫名稱 | 顯示用名稱 | `台北物流中心` |
| 緯度 | WGS84 緯度（-90 ~ 90） | `25.0478` |
| 經度 | WGS84 經度（-180 ~ 180） | `121.5170` |
| 開放時間 | 車輛最早出發時間 | `08:00` |
| 結束時間 | 車輛最晚回庫時間 | `20:00` |

#### 步驟 2：新增店面

1. 在「**店面**」卡片點擊「**＋ 新增店面**」
2. 每個店面需填寫：

| 欄位 | 說明 | 範例 |
|---|---|---|
| 店面名稱 | 顯示用名稱 | `信義松仁店` |
| 緯度 / 經度 | WGS84 座標 | `25.0338 / 121.5651` |
| 服務時間窗 | 最早/最晚可配送時間 | `10:00 ~ 13:00` |
| 需求量 | 單位：件/kg，視車隊設定而定 | `32` |
| 服務時長 | 到達後停留分鐘數 | `14` |

3. 可新增任意數量的店面，左側標題會顯示目前店面數量

#### 步驟 3：設定車隊

1. 在「**車隊設定**」卡片點擊「**＋ 新增車型**」
2. 每種車型需填寫：

| 欄位 | 說明 | 範例 |
|---|---|---|
| 車型名稱 | 顯示用名稱 | `大型貨車` |
| 載重容量 | 最大載重（與需求量單位相同） | `140` |
| 可用台數 | 此車型有幾台可派遣 | `2` |

> 注意：所有車型的總容量（容量 × 台數的加總）必須 >= 所有店面需求量的總和，否則無可行解。

#### 步驟 4：調整求解設定（選填）

在「**求解設定**」卡片中可調整：

| 欄位 | 預設值 | 說明 |
|---|---|---|
| 最長等待秒數（保底） | 10 秒 | GA 無改善或超時即停止，最大 300 秒 |
| 平均車速 (km/h) | 40 km/h | 用於由兩點距離反推行駛時間 |
| 隨機種子 | 42 | 固定種子可重現相同結果 |

#### 步驟 5：開始求解

點擊左側底部「**開始計算**」（按鈕由灰色變為可點擊，需至少有 1 個店面與 1 種車型）。

## 查看結果

### 地圖（中央）

- 各車輛路線以**不同顏色折線**顯示，顏色與右側結果面板對應
- 地圖標記：
  - **倉庫**：顯示起點/終點
  - **店面**：各路線顏色的圓形標記，點擊可查看：
    - 店面名稱與 ID
    - 抵達時間 / 離開時間
    - 等待時間（若提前到達時間窗前）
    - 距上一站距離
    - 目前累積載重

### 右側結果面板

每條路線顯示一張卡片，包含：
- 車型名稱與車輛索引
- 停靠順序（倉庫 → 店面 → ... → 倉庫）
- 各站抵達/離開時間
- 單程距離與累積載重
- 路線合計：總距離、總時長、總載重 / 容量

### Footer 統計列

| 欄位 | 說明 |
|---|---|
| 狀態 | 待機 / 求解中 / 完成 / 錯誤 |
| 總距離 | 所有路線合計距離（km） |
| 使用車輛 | 實際派出的車輛數 |
| 求解耗時 | GA 實際運行秒數 |

## 常見問題與錯誤處理

### Q：按下「開始計算」後一直轉圈？
求解複雜度與店面數、時間窗緊縮程度有關。預設最長 10 秒後會自動停止並回傳當前最佳解。若店面較多可適度調高「最長等待秒數」。

### Q：出現「總需求量超過總載重容量」錯誤？
需增加車輛台數或調高載重容量，確保所有需求皆可被服務。

### Q：出現「目前有另一個求解正在執行中」（HTTP 503）？
系統同時只允許一個求解任務。請等待目前求解完成後再試。

### Q：想重置所有資料？
點擊 Header 左上角的「**PyVRP Web**」Logo，即可清除所有輸入並回到初始狀態。

### Q：如何直接測試 API？
開啟 `http://127.0.0.1:8000/docs`，可使用 Swagger UI 直接呼叫 `/api/solve` 端點，貼上 JSON 資料進行測試。

## API 快速參考

### 健康檢查

```
GET http://127.0.0.1:8000/api/health
```

回應範例：
```json
{
  "status": "ok",
  "pyvrp_version": "0.5.0"
}
```

### VRP 求解

```
POST http://127.0.0.1:8000/api/solve
Content-Type: application/json
```

最小請求範例：
```json
{
  "depot": {
    "name": "倉庫",
    "location": { "lat": 25.0478, "lng": 121.5170 },
    "time_window": { "start": 480, "end": 1200 }
  },
  "stores": [
    {
      "id": "S001",
      "name": "店面A",
      "location": { "lat": 25.0611, "lng": 121.5319 },
      "time_window": { "start": 600, "end": 780 },
      "demand": 20,
      "service_minutes": 10
    }
  ],
  "vehicle_types": [
    { "name": "貨車", "capacity": 100, "num_available": 2 }
  ],
  "config": {
    "max_runtime_seconds": 10,
    "avg_speed_kmh": 40,
    "seed": 42
  }
}
```

> 時間欄位說明：`start` / `end` 為從當日 00:00 起算的分鐘整數。
> 例如 08:00 = 480，13:00 = 780，20:00 = 1200。

### HTTP 錯誤代碼

| 代碼 | 原因 |
|---|---|
| 422 | 輸入驗證失敗（需求超過容量、時間窗設定錯誤等）|
| 503 | 目前有另一個求解正在執行 |
| 504 | 求解逾時（理論上由 TimedNoImprovement 控制，正常不會觸發）|
| 500 | PyVRP 內部錯誤 |
