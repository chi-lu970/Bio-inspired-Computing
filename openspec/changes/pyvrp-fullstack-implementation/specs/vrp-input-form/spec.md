# 規格：VRP 輸入表單（vrp-input-form）

> **變更類型**：ADDED（全新 capability）
> **所屬變更**：`pyvrp-fullstack-implementation`
> **負責層級**：前端展示層

---

## 目的

提供使用者一個直觀的網頁表單，無需撰寫程式即可完整定義一個 VRP 問題實例（倉庫、店面、時間窗、需求量、車隊），並透過點擊按鈕送出至後端求解。

---

## ADDED Requirements

### Requirement: 倉庫輸入區塊

系統 SHALL 提供唯一一個倉庫輸入區塊，包含名稱、經度、緯度、開放時間窗（起 / 訖）等欄位。

#### Scenario: 使用者首次開啟頁面

- **WHEN** 使用者載入頁面
- **THEN** 倉庫區塊以預設名稱 `Depot` 顯示，經緯度欄位為空、時間窗預設為 `08:00 ~ 18:00`

#### Scenario: 經緯度範圍驗證

- **WHEN** 使用者輸入緯度 `91` 或經度 `181`
- **THEN** 該欄位顯示紅色邊框
- **AND** 顯示 tooltip 訊息：`緯度需介於 -90 ~ 90 / 經度需介於 -180 ~ 180`
- **AND** 「開始計算」按鈕被禁用

#### Scenario: 倉庫不可被刪除

- **WHEN** 使用者試圖透過 DOM 操作刪除倉庫區塊
- **THEN** 系統 SHALL 不提供任何刪除介面元素

---

### Requirement: 店面動態列表

系統 SHALL 允許使用者動態新增、編輯、刪除任意數量的店面，且每個店面包含 ID、名稱、經緯度、時間窗、需求量、服務時長等欄位。

#### Scenario: 新增店面

- **WHEN** 使用者點擊 `+ 新增店面` 按鈕
- **THEN** 列表底部新增一筆店面記錄，預設值：
  - `id`: 自動生成（如 `S001`、`S002`）
  - `name`: 空字串
  - `time_window`: `09:00 ~ 17:00`
  - `demand`: `10`
  - `service_minutes`: `10`

#### Scenario: 刪除店面

- **WHEN** 使用者點擊店面記錄右上角的 `×` 圖示
- **THEN** 該店面從列表移除
- **AND** 後續店面的 ID 不會自動重編號（避免使用者混淆）

#### Scenario: 時間窗順序驗證

- **WHEN** 使用者輸入店面時間窗 start=`17:00`、end=`09:00`
- **THEN** end 欄位顯示紅色邊框
- **AND** 顯示提示：`結束時間必須晚於開始時間`

#### Scenario: 需求量為負

- **WHEN** 使用者輸入 `demand: -5`
- **THEN** 欄位顯示紅色邊框與提示：`需求量不可為負數`

#### Scenario: 至少需要一個店面

- **WHEN** 列表內店面數量為 0
- **AND** 使用者點擊「開始計算」
- **THEN** 系統顯示提示：`請至少新增一個店面`，並阻止送出

---

### Requirement: 車隊配置區塊

系統 SHALL 允許使用者定義一種或多種車型，每種車型包含名稱、容量、可用數量。

#### Scenario: 新增車型

- **WHEN** 使用者點擊 `+ 新增車型`
- **THEN** 列表新增一筆車型記錄，預設名稱 `Vehicle Type N`、容量 `100`、數量 `2`

#### Scenario: 容量必須為正整數

- **WHEN** 使用者輸入容量 `0` 或負數
- **THEN** 欄位顯示錯誤提示：`容量必須大於 0`

#### Scenario: 至少需要一種車型

- **WHEN** 車型列表為空
- **AND** 使用者點擊「開始計算」
- **THEN** 系統顯示提示：`請至少新增一種車型`，並阻止送出

#### Scenario: 總容量檢查

- **WHEN** 所有店面需求總和 > 所有車輛總容量
- **THEN** 系統顯示**警告**（非錯誤）：`總需求量 X 超過總容量 Y，可能找不到可行解`
- **AND** 仍允許使用者送出

---

### Requirement: 表單序列化

系統 SHALL 提供 `collectFormData()` 函式，將表單內容序列化為符合 `SolveRequest` schema 的 JSON 物件。

#### Scenario: 完整序列化

- **WHEN** 使用者按下「開始計算」
- **AND** 表單通過所有驗證
- **THEN** 系統產生如下結構的 JSON：
  ```json
  {
    "depot": { "name": "...", "location": {...}, "time_window": {...} },
    "stores": [ {...}, {...} ],
    "vehicle_types": [ {...} ],
    "config": { "max_runtime_seconds": 10.0, "seed": 42, "avg_speed_kmh": 40.0 }
  }
  ```
- **AND** 時間欄位（HH:MM）已轉換為從 00:00 起算的分鐘整數

---

### Requirement: 範例資料載入

系統 SHALL 提供「載入範例」按鈕，一鍵載入預設的台北市示範資料填入表單。

#### Scenario: 載入範例

- **WHEN** 使用者點擊 header 的「範例資料載入」按鈕
- **AND** 表單原本為空
- **THEN** 系統 fetch `examples/taipei_demo.json` 並填入所有欄位
- **AND** 地圖自動 fitBounds 到所有點

#### Scenario: 載入範例時表單已有資料

- **WHEN** 使用者點擊「範例資料載入」
- **AND** 表單已有資料
- **THEN** 系統彈出確認對話框：`載入範例將覆蓋現有資料，確定繼續？`
- **AND** 使用者確認後才覆蓋

---

### Requirement: 即時驗證與按鈕狀態

系統 SHALL 即時驗證所有欄位，並在表單存在任何錯誤時禁用「開始計算」按鈕。

#### Scenario: 任一欄位錯誤

- **WHEN** 表單中存在任何驗證失敗的欄位
- **THEN** 「開始計算」按鈕呈現為禁用狀態（灰色、不可點擊）
- **AND** 按鈕 tooltip 顯示：`請先修正所有錯誤欄位`

#### Scenario: 全部欄位通過驗證

- **WHEN** 所有欄位通過驗證
- **THEN** 「開始計算」按鈕變為強調色（橘色），可點擊
